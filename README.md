# GitHub 上传 Agent

一个跑在**你自己电脑上**的小工具：用网页界面登录你的 GitHub，挑一个本地项目文件夹，勾选要上传的文件，一键提交到指定仓库；如果传错了，可以**撤回**。

零第三方依赖 —— 只用 Node 内置模块，不需要 `npm install`。

> 📖 **第一次用、不熟悉命令行？** 请先看 [使用指南（新手向）](./使用指南.md) —— 从装环境到完成上传，一步步带图说明。
>
> 下面这份 README 面向已经熟悉 Git / 命令行的用户，更偏技术细节。

---

## 快速开始

```bash
cd githubAgent
node server.js
```

然后浏览器打开 <http://127.0.0.1:5178>。

> 需要 Node 18 或更高版本（用到内置 `fetch` 与 `AbortController`）。

Windows 用户也可以直接双击 `start.bat`。

### 可选启动参数

| 参数 | 说明 |
| --- | --- |
| `--port <端口>` / `-p` | 监听端口，默认 `5178` |
| `--host <地址>` | 监听地址，默认 `127.0.0.1`（仅本机） |
| `--root <目录>` | 把可浏览的文件范围**限制**在该目录，可重复传入多个 |
| `--help` / `-h` | 显示帮助 |

```bash
# 只允许浏览 D:\projects 下的内容，更安全
node server.js --root "D:\projects"
```

## 五步操作流程

1. **登录 GitHub** —— 两种方式，任选其一（见下节）。
2. **选择项目文件夹** —— 弹出本机目录浏览器，支持盘符、桌面/文档/下载快捷入口、路径面包屑跳转。这一步**不需要登录**。
3. **勾选要上传的文件** —— 自动扫描成文件树，目录支持"全选/半选/未选"三态勾选，顶部可按文件名搜索过滤。默认跳过 `.git`、`node_modules`、`dist` 等，规则可在界面里改。
4. **选择目标仓库并上传** —— 可上传到已有仓库，也可顺手新建一个（可选私有）。能指定分支、提交说明；取消"允许覆盖"后，远端存在同名文件会**直接中止**而不是覆盖。上传过程有实时进度。
5. **上传记录与撤回** —— 列出本次会话里你上传过的提交，附两种撤回方式。

## 关于登录

### 方式一：访问令牌（推荐，最省事）

到 GitHub 生成一个带 `repo` 权限的 Personal Access Token：

- 界面里点"新建令牌（自动勾选 repo 权限）"直达生成页
- 粘贴进输入框，点"连接"

### 方式二：设备码登录（OAuth Device Flow）

不用手动生成令牌，在 GitHub 官方页面输一个短码即可授权。需要你先创建一个 OAuth App：

1. 打开 <https://github.com/settings/developers> → **New OAuth App**
2. 任意填写名称和主页地址（本地工具可以用 `http://localhost`）
3. **勾选 `Enable Device Flow`**（不勾选会报错）
4. 把生成的 **Client ID** 填进界面

> 设备码换来的令牌属于临时授权，不会被记住。

### 令牌放在哪里？

**只在浏览器内存里，以及每次请求的 HTTP 头里。** 服务端不写磁盘、不写日志。
勾选"在本机浏览器记住令牌"后会存进 `localStorage`，方便下次自动登录 —— 公共电脑请勿勾选。

## 撤回是怎么实现的

GitHub 的 REST API **没有 revert 端点**，所以这里给了两种语义明确的方案，在界面上可切换：

### 安全撤回（默认）

读出被撤回提交的**父提交**的内容树，然后以当前分支头为父提交、以那个树为新树，**再提交一次**。

- 文件内容回到上传前的状态
- 历史完整保留，可以再次撤销这次撤销
- 适合正常使用

### 强制回退

直接把分支指针（ref）拨回上传前的那个提交。

- 该提交及其之后的所有提交都会从分支上**消失**
- 历史被抹除，但仓库更"干净"
- 如果这次上传是仓库的第一个提交（没有父提交），强制回退会被拒绝，并提示你改用安全撤回 —— 因为此时安全撤回会退化为"删掉这批文件"

> 补充一个细节：强制回退只是让那些提交**不可达**，GitHub 上仍可能通过提交 SHA 直接访问到，直到被垃圾回收。

```bash

node smoke-test.js

# 2) 上传/撤回链路测试（自包含，会自己起一个 mock GitHub）
```

第 2 项值得说明一下：它在本机模拟了 GitHub 的 Git Data API（blob/tree/commit/ref 的对象模型），
然后跑**真实的**上传与撤回代码，断言"文件确实进了树""撤回后确实消失""base_tree 不让原有文件被删"
"force 回退确实让提交不可达"。因为这些语义光看代码是验不出来的。

## 安全说明

- 服务只监听 `127.0.0.1`，并在请求处理时校验 `Host`，拒绝非本机来源。
- 文件系统访问全部经过路径闸门（`lib/fsbrowse.js` 的 `createPathGuard`），
  挡住 `../` 穿越；默认放行本机全部盘符，用 `--root` 可收窄。
- 上传接口会把每个文件路径重新过一遍闸门，并确认它确实落在所选项目目录内。
- 上传前会剔除软链接，避免环形目录把扫描拖死。
- 未跟踪的隐藏文件（如 `.env`）不会被默认忽略规则跳过 —— 传入令牌前请留意你要传什么。

## 已知限制

- **单文件 95MB 上限**：GitHub 的 blob 接口不接受超过 100MB 的文件，界面里超限文件会标红且不可勾选。
- **不处理删除**：本工具只做上传，不会删除远端已存在的文件（撤回时例外）。
- **默认忽略 `dist` / `build` 等构建产物**：如果你的项目需要上传这些目录，在界面"忽略规则设置"里把它删掉再重新扫描。
- **空仓库的首个提交**：GitHub 建空仓库后没有任何分支，本工具会直接用你选的文件创建 `main` / 你指定的分支。
